# Ошибки HTTP API

Структура ответа сохраняется: `error.code` — название HTTP-статуса,
`error.message` — безопасное объяснение причины. Для ошибок входных полей
`error.fields` содержит отдельные сообщения. Имена Go-типов, SQL, stack trace,
ключи и исходные тексты внешних ошибок клиенту не передаются.

Сервисная PublicError хранит категорию, явно заданное публичное сообщение
и исходную ошибку. Категория и причина доступны через errors.Is/errors.As;
в журнал запроса передаётся исходная цепочка. HTTP-обработчик использует
только PublicMessage, а не Error(). Произвольное оборачивание известной
категории через fmt.Errorf не делает её текст безопасным для ответа.

Известная бизнес-ошибка объясняется конкретно. Для непредвиденного сбоя
ответ описывает неудавшуюся операцию или использует общий безопасный текст:
точная техническая причина остаётся диагностической информацией.

Пример конфликта конфигурации:

```json
{
  "error": {
    "code": "Conflict",
    "message": "this URL is already configured with a different browser_page_url"
  }
}
```

Один API URL использует общие `type`, `browser_page_url` и `json_source`.
Новый монитор должен передать совпадающие настройки. Отсутствующий
`browser_page_url` означает отсутствие браузерного источника. Обязательный
`page_url` описывает ссылку на товар и не включает браузерное получение JSON.
Сохранённые настройки другого монитора в ответе не раскрываются.

Другие причины: достигнут лимит трёх правил, hostname уже настроен,
hostname используется мониторами, монитор не найден или не может быть
возобновлён в текущем состоянии. Неверный email и неверный пароль дают
одно общее сообщение, без раскрытия наличия аккаунта.

Idempotency-Key сохраняет ответ, включая объяснение ошибки. Для успешно созданного
монитора повтор POST /me/monitors возвращает его актуальное состояние с 201,
а после удаления — 404, пока ключ не истёк.
Повтор старого запроса со старым ключом может вернуть прежний текст ошибки.
После изменения тела нужен новый ключ. Если результат создания неизвестен
из-за сетевого или серверного сбоя, не создавайте другой запрос автоматически:
проверьте результат и повторите исходный запрос с прежним ключом.
