# Серверное развёртывание

GitHub Actions проверяет Go-пакеты с integration-тегом и изолированными PostgreSQL, Redis и RabbitMQ, а также скрипты Bruno. Для проверки генератора нагрузки CI создаёт отдельную базу и небольшой синтетический набор данных. После успешной проверки push в `prod` собирает образ с тегом commit SHA в GHCR и запускает развёртывание по SSH. Нагрузочные k6 и реальные внешние интеграции автоматически не запускаются.

## Подготовка

- На сервере нужны Docker Engine, Compose plugin, `bash`, `tar` и учётная запись SSH с доступом к Docker. Архитектура сервера должна поддерживаться публикуемыми образами. Настройте доступ сервера к GHCR и к отслеживаемым внешним сервисам.
- В каталоге развёртывания создайте `.env` по `.env.example`: замените пароли и секреты, согласуйте `DATABASE_URL`, `RABBITMQ_URL` и учётные данные контейнеров. Добавьте `GRAFANA_ADMIN_USER` и `GRAFANA_ADMIN_PASSWORD`. Compose берёт `.env` с сервера; workflow его не передаёт и не перезаписывает.
- Подготовьте сертификаты fetcher в `FETCHER_CERT_DIR` по [инструкции](fetcher/README.md). При относительном пути он отсчитывается от каталога развёртывания. Сертификаты и ключи остаются на сервере.
- Создайте GitHub Actions secrets: `GO_MODULE_GITHUB_TOKEN` с правом чтения приватного Go-модуля; `GHCR_READ_TOKEN` с правом чтения всех приватных образов приложения и fetcher; `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_PATH` (абсолютный путь без пробелов), `DEPLOY_SSH_KEY` и `DEPLOY_KNOWN_HOSTS` (проверенная запись сервера в формате OpenSSH known_hosts). Учётная запись владельца репозитория используется для входа в GHCR. `GITHUB_TOKEN` публикует образ и должен иметь право записи пакетов.
- Секреты не передаются workflow из pull request внешнего fork; для такой проверки требуется доверенная среда с доступом к приватному модулю.

На первом запуске используется пустая база. Автоматического удаления существующих volumes нет. Миграции выполняются при каждом деплое до запуска приложения и пропускают уже применённые версии. Сначала останавливаются процессы приложения: при ошибке миграции деплой завершится с ошибкой, а приложение останется остановленным до устранения причины. Само обновление схемы назад не откатывается автоматически.

API и Grafana доступны только на loopback сервера. Например, для стандартных портов создайте туннель `ssh -L 8080:127.0.0.1:8080 -L 3010:127.0.0.1:3010 user@host`; используйте значения портов из серверного `.env`. PostgreSQL, RabbitMQ, Redis, Prometheus и Loki не публикуются на хосте. Redis находится в отдельной внутренней сети с клиентами и exporter.

Workflow передаёт на сервер Compose, конфигурацию Docker и скрипт развёртывания. Для входа в GHCR создаётся временный Docker config, который удаляется после выполнения. Проверьте результат в GitHub Actions и через `docker compose -f docker-compose.server.yml ps` на сервере; для ручной команды нужно предварительно установить `MONITORING_IMAGE` в образ нужного коммита. Успешное создание контейнеров не доказывает доступность внешних сервисов и корректность реальных уведомлений.
