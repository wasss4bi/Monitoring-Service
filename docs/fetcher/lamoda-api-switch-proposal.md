## Подтверждённые данные

JSON API `https://www.lamoda.ru/api/v1/product/get?is_hybrid_supported=true&size_id=0&sku=MP002XM0281A`
через HTTP_JSON/mTLS gRPC с предоставленной анонимной сессией дважды вернул
HTTP200: `sku=MP002XM0281A`, `price=21591`, `sizes[9].stock_quantity=1`.
Повторный запрос включал новый regex ключ, все четыре значения имели
VALUE_ORIGIN_NETWORK. Содержимое ответа не сохранялось. Обновлённая сессия
сохранена только в защищённом ignored-файле.

INLINE_JSON по странице товара с той же сессией получает CAPTCHA.
Два запроса API без перенесённых cookies завершились DeadlineExceeded;
этого недостаточно для вывода, что анонимный API обязательно запрещён.

## Конкретный план

1. В короткой транзакции заблокировать endpoint9 и его мониторы. Проверить
   точный URL, прежний json_source, пять существующих подписчиков и отсутствие
   активных мониторов/pending/fetching заданий. При расхождении остановиться.
2. У endpoint9 очистить только `json_source`, выбрав уже существующий режим
   HTTP_JSON вместо INLINE_JSON. Повысить generation пяти подписчиков для
   отклонения старых результатов. Их правила, статусы и сессии сохранить;
   завершённые мониторы не перезапускать. Исходный json_source сохранить
   локально для обратного переключения с новым повышением generation.
3. Создать одну явно подписанную тестовую копию монитора22 с исходными
   условиями `price <= 28990` и `sizes[9].stock_quantity >= 1` и исходным
   rules_count_to_finish. Только эта копия использует `session_mode=provided`
   и зашифрованную анонимную сессию из локального файла.
4. Проверить штатный scheduler → outbox/RabbitMQ → worker → Fetcher →
   вычисление правил → notification worker. Сообщение в Telegram отправляет
   обычный notification worker после реального результата.

Новый HTTP/gRPC контракт и особый код Lamoda не нужны. Bootstrap hostname,
остальные сайты и исходные правила не меняются. Тестовая копия остаётся
в истории с явным названием.

## Ограничение

Provided-сессия не обновляется автоматически через PrepareSession. При её
отказе нужен новый анонимный экспорт из браузера. Этот вариант подтверждает
работающий путь получения данных, но не гарантирует бессрочную автономную
работу Lamoda. Переход всех существующих managed-мониторов на provided не
предлагается. Для полностью автоматического managed bootstrap нужен отдельно
подтверждённый рабочий способ получения сессии.
